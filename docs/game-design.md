# 《赶鸭子上架》- 游戏设计文档

> **3D 联机合作赶鸭子派对游戏**
> 引擎：UrhoX | 视角：胡闹厨房式固定等距俯瞰 | 联机：1-4 人

---

## 一、游戏概述

### 1.1 一句话描述

玩家操控矮人角色，在充满障碍的 3D 关卡中合作将鸭群赶入目标区域（"架子"），完成限时挑战。

### 1.2 游戏名称含义

"赶鸭子上架"是一句中国俗语，原意是强迫人去做力所不能及的事。游戏巧妙地将这个比喻变成了字面意义——你真的要把一群不听话的鸭子赶到架子上。

### 1.3 核心卖点

| 卖点 | 描述 |
|------|------|
| **欢乐合作** | 1-4 人联机合作，配合走位赶鸭，欢笑不断 |
| **鸭子 AI** | 鸭群拥有仿真集群行为，受惊乱跑、互相跟随、上架后还会自由活动甚至逃跑 |
| **关卡多样** | 农场、市集、河流、厨房等主题关卡，机关各异 |
| **轻松无压** | 参考《羊羊集合啦》的"无惩罚"设计理念，失败不扣分，只有正向激励 |
| **金币经济** | 每局通过上架鸭子和星级评价赚取金币，积累购买道具和服装 |

### 1.4 参考游戏分析

#### 《羊羊集合啦！》(Sheepherds!)

- **核心玩法**：玩家扮演牧羊犬，通过跑位和"吠叫"引导羊群到达目标地点
- **羊群 AI**：羊群拥有集群行为（Flocking），小羊互相跟随、受玩家靠近/吠叫影响而移动
- **联机模式**：1-4 人，支持本地和在线合作
- **设计理念**：无时间限制、无惩罚、无强制分工，主打轻松社交
- **关卡设计**：22 个关卡，包含河流、潮汐、传送阵、颜色合成等多种机制
- **评价**：Steam 98% 好评率

**我们借鉴的要素**：
- 核心赶动物玩法（牧羊犬 → 矮人，羊 → 鸭子）
- 集群 AI 行为系统
- 无压力合作设计理念
- 多关卡+渐进式解锁机制

**我们的差异化**：
- 角色从牧羊犬改为更具表现力的矮人角色（可持道具、有更多动作）
- 动物从羊改为鸭子（水陆两栖，行为更丰富）
- 增加道具系统（面包屑引诱、围栏放置等）
- 视角采用胡闹厨房式固定俯瞰（而非自由相机）
- 金币经济系统，积累奖励购买道具和服装

#### 《胡闹厨房》(Overcooked!) — 视角参考

- **视角类型**：固定 3/4 等距俯瞰视角（Isometric Top-Down）
- **相机参数**：水平旋转 45°，垂直倾斜约 30-35°，固定不可旋转
- **设计目的**：所有玩家共享同一画面，清晰看到整个关卡布局，便于分工协作
- **适配优势**：固定视角降低了 3D 游戏的操控门槛，非常适合合作类派对游戏

## 二、玩法设计

### 2.1 核心循环

```
进入关卡 → 鸭群散布在地图中 → 玩家合作赶鸭 → 鸭子进入目标区域 → 达成目标数量 → 关卡完成
     ↑                                                                    ↓
     └──────────── 解锁新关卡/新道具 ← 获得星级评价 ← 获得金币奖励 ←────────┘
```

### 2.2 玩家操控

| 操作 | 按键 | 效果 |
|------|------|------|
| 移动 | WASD / 摇杆 | 矮人角色移动 |
| 冲刺 | Shift / 手柄按键 | 短暂加速（6.5 m/s），可以快速绕到鸭群前方 |
| 拍手驱赶 | 空格 / A键 | 发出声响，驱散附近 5m 内鸭子（冷却 0.8s） |
| 地图预览 | P | 切换等距俯瞰全景预览（可开启坐标网格） |

> **注**：道具系统（使用道具 E / 拾取 F）规划中，尚未实现。

### 2.3 鸭子 AI 行为系统

鸭子是游戏的核心，采用 Boids 集群算法 + 状态机实现：

#### 基础行为（Boids 算法 + 状态机）

| 状态 | 行为描述 | 触发条件 |
|------|---------|---------|
| **闲逛 (idle)** | 鸭子随机走动，偶尔停下啄地 | 默认状态 |
| **受惊 (scared)** | 鸭子快速逃离驱赶源，方向大致相反 | 玩家靠近 3.5m / 拍手 5m |
| **上架 (settled)** | 鸭子进入目标区域后安定，在围栏内自由活动 | 在目标区域停留 1.5s |

#### 上架后行为（已实现）

上架的鸭子并非静止不动，而是在围栏内表现出生动的自主行为：

| 行为 | 描述 | 参数 |
|------|------|------|
| **围栏内闲逛** | 以 0.6 m/s 速度在目标区域内随机漫步 | 碰到边界自动转向 |
| **周期性跳跃** | 每 3-7 秒随机跳一次，高度 0.25m | sin 曲线模拟 |
| **逃跑判定** | 所有玩家距离 >10m 时，每 15s 有 1/15 概率逃跑 | 逃跑后恢复 idle 状态 |

逃跑机制增加了策略深度——玩家不能把鸭子赶进围栏后就完全不管，需要保持一定的"巡逻"意识。

#### 集群行为参数（已调优）

```
分离力 (Separation)：权重 1.5，最小间距 0.8m
聚合力 (Cohesion)：权重 0.8，感知范围 4.0m
对齐力 (Alignment)：权重 0.3
恐惧力 (Fear)：权重 3.0，玩家近距离 3.5m / 拍手 5.0m
闲逛力 (Wander)：权重 0.5，随机力 0.3
边界力 (Boundary)：权重 2.0
避障力 (Obstacle)：权重 2.5
```

#### 特殊鸭子类型（规划中）

| 鸭子类型 | 特点 | 赶法策略 |
|---------|------|---------|
| **普通鸭** | 标准行为，容易驱赶 | 直接靠近拍手（**已实现**） |
| **头鸭（领队鸭）** | 体型稍大，其他鸭子跟随它 | 重点赶头鸭，其他鸭子会跟上 |
| **倔强鸭** | 受惊后随机方向逃跑，不一定远离玩家 | 需要多人合围 |
| **水鸭** | 偏好待在水中，上岸后很快想回水 | 用面包屑引诱离开水面 |
| **小鸭仔** | 速度快、体型小、紧跟妈妈鸭 | 赶妈妈鸭就行 |

### 2.4 道具系统（规划中）

| 道具 | 效果 | 获取方式 |
|------|------|---------|
| **面包屑** | 撒在地上，吸引鸭子过来吃（持续 5 秒） | 地图中拾取 |
| **临时围栏** | 放置一段矮围栏，阻挡鸭子通过 | 地图中拾取 |
| **扩音器** | 拍手驱赶范围扩大 2 倍 | 关卡奖励 |
| **鸭子雨衣** | 穿上后鸭子不认为你是威胁（可近距离引导） | 高级关卡解锁 |

### 2.5 关卡设计

#### 关卡结构

每关包含：
- **目标鸭子数量**：需要赶入目标区域的最低鸭子数
- **总鸭子数量**：地图上的鸭子总数
- **目标区域**："架子" — 一个明显标识的目标围栏
- **障碍与机关**：增加赶鸭难度的地形和互动元素

#### 关卡主题规划（每章 1 关，共 5 关）

| 关卡 | 主题 | 核心机制 | 鸭子类型 | 鸭子数 | 状态 |
|------|------|---------|---------|--------|------|
| 第 1 关 | **阳光牧场** | 基础赶鸭教学，开阔地形 + 栅栏引导 | 普通鸭 | 8 只 | **已完成** |
| 第 2 关 | **溪流农庄** | 引入水域，鸭子会下水变难赶 | 普通鸭 + 水鸭 | 10 只 | 规划中 |
| 第 3 关 | **丰收市集** | 狭窄巷道 + 道具面包屑 | 普通鸭 + 头鸭 | 10 只 | 规划中 |
| 第 4 关 | **泥泞雨天** | 泥地减速区 + 倔强鸭 | 普通鸭 + 倔强鸭 | 12 只 | 规划中 |
| 第 5 关 | **鸭子乐园** | 全机制综合 + 妈妈鸭带小鸭仔 | 全类型混合 | 15 只 | 规划中 |

### 关卡一：阳光牧场

> 详细设计文档已独立拆分，见 **[level-1-sunny-farm.md](level-1-sunny-farm.md)**

**概要**：18m×12m 牧场 + 外围环境（50m×40m），8 只普通鸭，教学+建立核心乐趣。通过地图布局自然引导玩家学会移动、拍手驱赶，不设强制教程弹窗。

### 2.6 评分与金币奖励

#### 星级评价

| 星级 | 条件 | 奖励 |
|------|------|------|
| ★☆☆ | 赶入 5 只鸭子 | 解锁下一关 |
| ★★☆ | 赶入 7 只鸭子 | 解锁新道具 |
| ★★★ | 赶入全部 8 只鸭子 | 解锁角色皮肤 |

#### 金币系统（已实现）

金币是游戏的内部经济货币，关卡结算时获取：

| 来源 | 金币数 | 说明 |
|------|--------|------|
| 上架鸭子 | 每只 +1 | 赶入目标区的鸭子数量 |
| 星级奖励 | 每颗星 +1 | 星级评价转换为额外金币 |

**计算公式**：`本局金币 = 上架鸭子数 + 星级数`

**示例**：上架 8 只鸭子（★★★）→ 8 + 3 = 11 金币

**存储**：使用 `clientCloud` 云存储，跨设备持久化，支持原子增量操作。

**用途**（规划中）：
- 在小木屋附近找农场主购买道具
- 购买角色服装/皮肤
- 解锁特殊道具

#### 无惩罚设计

- 没有"失败"状态，总能完成关卡
- 没有时间限制（但时间作为评价参考）
- 上架鸭子有小概率逃跑，但不会导致失败，增加趣味性

## 三、联机合作设计

### 3.1 网络架构

采用 **客户端-服务端（C/S）** 架构：

```
┌──────────┐     ┌──────────┐
│ 客户端 1  │────▶│          │
│ (玩家 1)  │◀────│          │
└──────────┘     │          │
┌──────────┐     │  服务端   │
│ 客户端 2  │────▶│ (权威)   │
│ (玩家 2)  │◀────│          │
└──────────┘     │          │
┌──────────┐     │          │
│ 客户端 3  │────▶│          │
│ (玩家 3)  │◀────│          │
└──────────┘     │          │
┌──────────┐     │          │
│ 客户端 4  │────▶│          │
│ (玩家 4)  │◀────│          │
└──────────┘     └──────────┘
```

同时支持 **单机模式（Standalone）**，所有逻辑在本地运行，无需服务器。

### 3.2 同步策略

| 数据类型 | 同步方式 | 频率 |
|---------|---------|------|
| 玩家位置/朝向 | 服务端权威 + 客户端预测 | 每帧 |
| 鸭子位置/状态 | 服务端计算，广播给客户端 | 10-15 次/秒 |
| 拍手驱赶效果 | 客户端发送事件 → 服务端计算影响 | 事件驱动 |
| 鸭子上架/逃跑 | 服务端判定 → 广播 DUCK_SETTLED / DUCK_ESCAPED | 事件驱动 |
| 关卡结果 | 服务端计算星级+金币 → 广播 GAME_RESULT | 事件驱动 |
| 金币存储 | 各客户端独立保存到 clientCloud | 事件驱动 |

### 3.3 网络事件

| 事件名 | 方向 | 数据 |
|--------|------|------|
| `E_ClientReady` | 客户端→服务端 | 客户端已准备就绪 |
| `E_AssignRole` | 服务端→客户端 | 分配玩家角色索引 |
| `E_PlayerClap` | 客户端→服务端 | 拍手位置 |
| `E_DuckSettled` | 服务端→客户端 | 鸭子 ID、上架数量、星级 |
| `E_DuckEscaped` | 服务端→客户端 | 鸭子 ID |
| `E_GameResult` | 服务端→客户端 | 星级、上架数、总鸭数、用时、获得金币 |

### 3.4 合作机制

| 机制 | 描述 |
|------|------|
| **包抄走位** | 2-4 人从不同方向逼近鸭群，形成包围圈 |
| **驱赶接力** | A 玩家把鸭群赶到中途，B 玩家在前方接手继续赶 |
| **巡逻防逃** | 上架鸭子可能逃跑，需要有人留在目标区附近看守 |
| **分头行动** | 分散的鸭子需要多人分别去赶 |

### 3.5 匹配与房间

- 支持 1-4 人游玩
- 匹配模式：`free_match`，支持秒开（`immediately_start`）
- 单机模式下全部逻辑本地运行，体验一致

## 四、视觉与美术风格

### 4.1 美术方向

- **整体风格**：卡通渲染（低多边形 Low-Poly + 鲜艳配色）
- **参考游戏**：《胡闹厨房》的清爽卡通风 + 《羊羊集合啦》的温馨田园感
- **色调**：明亮、温暖、饱和度中高
- **3D 模型**：全部使用 AI 生成的 GLB 模型导入，低面数卡通风格

### 4.2 相机设置

固定等距俯瞰视角，当前实际参数：

```
相机参数：
- 投影：透视投影（非正交）
- 看向：地图中心偏南 (9, 0, 5.5)
- 距离：17m
- 水平旋转 (Yaw)：0°（围栏与屏幕平行）
- 垂直倾斜 (Pitch)：-55°
- FOV：42°
- 近裁面：0.5m，远裁面：200m
- 交互：不可旋转、不可缩放

优势：
- 所有玩家共享同一画面
- 农场填满画面，外围环境可见边缘
- 降低 3D 操控门槛
- 适合多人合作场景
```

### 4.3 角色设计

**矮人角色**（已实现 — 3D 模型）：
- 使用 AI 生成的矮人 GLB 模型（dwarf.mdl）
- 支持拍手动画（身体压缩+手臂抬起）和行走摇摆动画
- 4 名玩家通过不同颜色区分（红/蓝/绿/黄）

**鸭子**（已实现 — 3D 模型）：
- 使用 AI 生成的鸭子 GLB 模型（duck.mdl）
- 白色身体 + 橙黄嘴
- 上架后身体颜色微变（微绿色），头顶显示 ★ 标记
- 行走时有摇摆动画
- 受惊时播放随机嘎嘎叫音效（5 种变体）

使用 `urhox-libs/UI` 组件系统（Yoga Flexbox + NanoVG），AstroonTheme 主题：

## 七、技术方案

| 项目 | 选型 |
|------|------|

### 7.3 核心算法：Boids 鸭群系统

```lua
-- 每帧更新每只鸭子的速度（简化伪代码）

function UpdateDuck(duck, allDucks, players)
    local steer = Vector3.ZERO

    -- 1. 分离：避免与其他鸭子重叠 (权重 1.5)
    steer = steer + CalcSeparation(duck, allDucks) * 1.5

    -- 2. 聚合：向群体中心靠拢 (权重 0.8)
    steer = steer + CalcCohesion(duck, allDucks) * 0.8

    -- 3. 对齐：趋向同伴方向 (权重 0.3)
    steer = steer + CalcAlignment(duck, allDucks) * 0.3

    -- 4. 恐惧：远离玩家 (权重 3.0)
    for _, player in ipairs(players) do
        local dist = (duck.pos - player.pos):Length()
        if dist < 3.5 then  -- fearRadius
            local flee = (duck.pos - player.pos):Normalized()
            steer = steer + flee * 3.0 * (1 - dist / 3.5)
        end
    end

    -- 5. 避障 (权重 2.5)
    steer = steer + CalcObstacleAvoidance(duck) * 2.5

    -- 6. 边界约束 (权重 2.0)
    steer = steer + CalcBoundary(duck) * 2.0

    -- 应用到鸭子速度（限速 3.5 m/s）
    duck.velocity = duck.velocity + steer * dt
    duck.velocity = ClampMagnitude(duck.velocity, 3.5)
    duck.position = duck.position + duck.velocity * dt
end
```
